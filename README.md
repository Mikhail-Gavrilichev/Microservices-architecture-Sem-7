# Microservices-architecture-Sem-7 · ФИТ-231

Учебный проект из двух микросервисов. Весь проект запускается **одной командой** из корня репозитория.

| Сервис | Что делает | Frontend | API / Swagger |
|---|---|---|---|
| **Готовые формы** (`gameforms-service`) | подготовка игр, задач и комплектов форм | http://localhost:8081 | http://localhost:8080/swagger |
| **Вердикт** (`checking-service`) | проверка работ жюри | http://localhost:8091 | http://localhost:8090/swagger |

## Запуск

```bash
docker compose up --build
```

Порядок запуска: PostgreSQL (с healthcheck) → backend → frontend для каждого сервиса. Первый запуск собирает .NET-образы и занимает несколько минут.

* Остановить, сохранив данные: `docker compose down`
* Остановить и удалить тома (БД и фотографии): `docker compose down -v`

Пароли локальных БД по умолчанию учебные. Их можно переопределить переменными `POSTGRES_PASSWORD` (формы) и `CHECKING_DB_PASSWORD` (проверка) **до первого запуска**, например:

```bash
CHECKING_DB_PASSWORD=secret docker compose up --build
```

Или скопируйте `.env.example` в `.env` и отредактируйте значения (Compose подхватывает `.env` автоматически).

Порты наружу: `8080`/`8081` — сервис форм, `8090`/`8091` — сервис проверки. PostgreSQL наружу не публикуется.

## От выданной формы до результата

1. На http://localhost:8081 создайте игру, задачу с условием и эталоном, опубликуйте их. Создайте комплект команды, добавьте форму, подготовьте, напечатайте и выдайте комплект. На этом работа первого сервиса заканчивается.
2. На http://localhost:8091 войдите как **Участник**, выберите выданную форму, введите ответ и нажмите **Отправить**. Команда подставляется из формы. Решение создаётся в БД второго сервиса. Второе решение для той же формы не создаётся.
3. Загрузите JPEG/PNG до 8 МБ, укажите номер формы на фото и подтвердите читаемость и видимость ответа. Сервер декодирует фото и сверяет номер. При отклонении используйте **Отправить повторно**, исправьте ответ и прикрепите фото к тому же решению. Только после успешной проверки фото создаётся заявка жюри.
4. Войдите как **Жюри**, создайте члена жюри, если это первый вход. Поставьте зачёт, незачёт или явно передайте спорную работу старшему. Если обычные судьи заняты, следующая первичная работа ждёт, а не назначается свободному старшему. Итог сохраняется в БД второго сервиса (`GET /api/results`).

### Направление HTTP и основные маршруты

Сервис решений **читает** в сервисе подготовки `GET /api/forms/issued` (также принимает `?formId=…`) и существующий `GET /api/tasks/{id}`. При создании решения сервер сверяет форму, команду, игру и задачу, сохраняет снимок условия и эталона. В каталоге участника эталона нет. Адрес в Compose задаётся `GAMEFORMS_URL` (по умолчанию `http://gameforms-backend:8080`). Базы раздельные. Запускайте общий Compose: в отдельном сервисе проверки демонстрационного каталога больше нет.

| Действие | API второго сервиса |
|---|---|
| Получить доступные выданные формы | `GET /api/catalog/forms` |
| Создать решение | `POST /api/submissions` — JSON: `gameId`, `formId`, `taskId`, `teamId`, `answer` |
| Прикрепить фотографию | `POST /api/submissions/{id}/photo` — multipart: `file`, `photoFormId` |
| Проверить фото и состояние | `POST /api/submissions/{id}/validate-photo` — JSON: `isPhotoReadable`, `isAnswerVisible` |
| Исправить отклонённое решение | `POST /api/submissions/{id}/resubmit` — JSON: `answer` |

### При обновлении с предыдущей версии

Сделайте резервную копию БД. Миграция убирает из таблицы форм ответ, фотографию и признаки старой доставки; решения и результаты в БД жюри не изменяются. Если в первом сервисе остались **неотправленные** работы, миграция остановится, не удаляя их. Доставьте их предыдущей версией и проверьте наличие во втором сервисе перед повторным запуском новой. Не удаляйте тома командой `down -v`.

## Демонстрационный вход (без авторизации)

На фронтенде проверки нет регистрации, паролей, JWT и запросов авторизации. При открытии http://localhost:8091 появляется экран **«Кто вы?»**: имя + роль → кнопка «Войти».

| Роль | Что видит |
|---|---|
| Участник | отправка решения, загрузка фото, подтверждение читаемости |
| Жюри | экран быстрой проверки работ |
| Старшее жюри | тот же экран + переданные работы |
| Организатор | тестовые работы, жюри, очередь, результаты |

Выбранный пользователь хранится в `localStorage`, кнопка «Сменить пользователя» возвращает к экрану входа. Данные входа на backend не отправляются.

## Проверка работы за 5 секунд

Экран жюри — одна работа на экран: слева **ответ участника** и фото, справа **эталонный ответ**. Внизу две большие кнопки.

* `1` — зачёт, `2` — незачёт; после решения автоматически открывается следующая работа.
* `←` / `→` — переход между работами без оценки.
* Повторно оценить уже проверенную работу нельзя: кнопки блокируются, в шапке работы появляется пометка «уже проверено».
* Счётчик `124 / 2500` и тонкая полоса прогресса в шапке; позиция и прогресс сохраняются между перезагрузками.
* В DOM всегда только одна работа — ограничение времени проверки не зависит от числа работ.

### Тестовые работы

Кнопка **«Создать 100 тестовых работ»** (на пустом экране жюри или в панели «Организатор») создаёт 100 решений в `localStorage`:

* разнообразные ответы, часть совпадает с эталоном, часть — нет;
* каждое 12-е решение с тестовой картинкой формы (SVG data URL), остальные — с плейсхолдером;
* никаких запросов на backend, база данных не меняется;
* «Очистить тестовые работы» и «Сбросить прогресс проверки» удаляют данные.

Тестовые работы попадают в тот же экран проверки, что и реальные, — сразу после входа под ролью «Жюри».

## Фотографии

Фото в интерфейсе проверки отдаётся существующим маршрутом `GET /api/checks/{id}/photo`:

* путь нормализуется на фронтенде: относительный, абсолютный или `data:`-URL приводятся к виду, который отдаёт nginx;
* если фото нет — понятный плейсхолдер «Фотография не приложена»;
* если изображение не загрузилось — сообщение об ошибке и кнопки «Повторить» / «Открыть отдельно» вместо пустого блока;
* клик по фото открывает увеличенный просмотр (Esc или клик — закрыть);
* при подтверждении читаемости участник видит предпросмотр загруженного файла — раньше проверить читаемость было нельзя, потому что фото не показывалось вообще.

## Проверка после запуска

1. http://localhost:8091 → имя «Анна», роль «Жюри» → «Войти».
2. На пустом экране нажать «Создать 100 тестовых работ».
3. Проверить несколько работ клавишами `1` / `2`, затем перезагрузить страницу — позиция и счётчик сохранятся.
4. «Сменить пользователя» → роль «Участник» → отправить решение, загрузить JPEG/PNG, подтвердить читаемость.
5. «Сменить пользователя» → роль «Жюри» с именем из шага 4 → в шапке появится кнопка создания члена жюри, после неё реальная работа откроется на том же экране проверки.
6. Роль «Организатор» → очередь, жюри и результаты.
